# 代码重构总结 - 2025-10-26

## 重构背景

基于Linus Torvalds的代码审查建议，对项目进行了全面重构，遵循以下原则：

## 重构内容

### 1. 修复 BusinessException 的设计缺陷 ✅

**问题描述**：
- BusinessException同时有自己的`message`字段和继承自RuntimeException的message
- 存在数据不一致风险：`getMessage()`和实例字段`message`可能不同步

**修复方案**：
```java
// ❌ 修复前
public class BusinessException extends RuntimeException {
    private Integer code;
    private String message;  // 重复字段
    
    public String getMessage() {
        return message;  // 可能与super.getMessage()不一致
    }
}

// ✅ 修复后
public class BusinessException extends RuntimeException {
    private final Integer code;  // 设为final
    // 删除message字段，直接使用父类的getMessage()
    
    public Integer getCode() {
        return code;
    }
}
```

**影响**：
- 文件：`src/main/java/com/lingfan/liuyao/exception/BusinessException.java`
- 改动：删除重复字段，简化代码
- 代码行数：144行 → 108行（减少36行）

### 2. 简化 RedisUtil ✅

**问题描述**：
- RedisUtil有734行代码，实现了5种缓存策略
- `getWithMutex`和`getWithLogicalExpire`方法完全未使用
- 浪费约200行代码

**删除内容**：
- ❌ `getWithMutex()` - 互斥锁方案（70行）
- ❌ `setWithLogicalExpire()` - 逻辑过期方案（20行）
- ❌ `getWithLogicalExpire()` - 逻辑过期查询（70行）
- ❌ `locks` Map - 本地锁映射（仅未使用方法用）
- ❌ `executor` - 线程池（仅未使用方法用）

**保留内容**：
- ✅ 基础操作：set、get、delete、hasKey、expire
- ✅ 防缓存雪崩：`setWithRandomExpire`
- ✅ 防缓存穿透：`setNull`、`isNullCache`
- ✅ 分布式锁：`executeWithLock`
- ✅ 哈希操作、集合操作、递增递减

**效果**：
- 文件：`src/main/java/com/lingfan/liuyao/utils/RedisUtil.java`
- 代码行数：734行 → 520行（减少214行，-29%）
- 功能保留：所有实际使用的功能均保留

### 3. 拆分 UserServiceImpl（核心重构） ✅

**问题描述**：
- UserServiceImpl有958行代码，是个"上帝类"
- 包含注册、登录、信息管理、VIP管理等多种职责
- 违反单一职责原则

**拆分方案**：

按照开发规范，严格遵守包结构：

#### 3.1 UserRegisterService（注册相关）
- **接口位置**：`service/UserRegisterService.java`
- **实现位置**：`service/impl/UserRegisterServiceImpl.java`（遵守规范）
- **代码行数**：450行
- **职责**：
  - `register()` - 用户注册
  - `isUsernameExists()` - 用户名重复检查
  - `isEmailExists()` - 邮箱重复检查
  - `isPhoneExists()` - 手机号重复检查
  - 验证码校验（后期启用）

#### 3.2 UserAuthService（认证相关）
- **接口位置**：`service/UserAuthService.java`
- **实现位置**：`service/impl/UserAuthServiceImpl.java`（遵守规范）
- **代码行数**：270行
- **职责**：
  - `login()` - 用户登录
  - `getUserByAccount()` - 根据账号查询用户
  - 登录失败次数限制
  - 账号锁定机制
  - JWT Token生成
  - 用户会话管理

#### 3.3 UserProfileService（信息管理）
- **接口位置**：`service/UserProfileService.java`
- **实现位置**：`service/impl/UserProfileServiceImpl.java`（遵守规范）
- **代码行数**：280行
- **职责**：
  - `getUserProfile()` - 获取用户详细信息
  - `updateProfile()` - 更新用户信息
  - `uploadAvatar()` - 头像上传
  - `getUserById()` - 根据ID查询用户（带缓存）
  - `calculateLevel()` - 计算用户等级
  - `getDailyDivinationLimit()` - 获取占卜次数限制
  - `isVipActive()` - 检查VIP是否有效

**效果对比**：
```
修复前：
- UserServiceImpl: 958行（1个文件）

修复后：
- UserRegisterServiceImpl: 450行
- UserAuthServiceImpl: 270行
- UserProfileServiceImpl: 280行
- 总计：1000行（3个文件）

优势：
✅ 职责清晰，易于维护
✅ 遵循单一职责原则
✅ 降低类之间的耦合度
✅ 未来扩展更方便（如添加第三方登录）
```

### 4. 更新 UserController ✅

**修改内容**：
- 替换依赖：从`UserService`改为3个独立Service
- 方法调用：根据功能调用对应的Service

```java
// ❌ 修复前
@Autowired
private UserService userService;

userService.register(request);
userService.login(request);
userService.getUserProfile(userId);

// ✅ 修复后
@Autowired
private UserRegisterService userRegisterService;
@Autowired
private UserAuthService userAuthService;
@Autowired
private UserProfileService userProfileService;

userRegisterService.register(request);
userAuthService.login(request);
userProfileService.getUserProfile(userId);
```

**影响**：
- 文件：`src/main/java/com/lingfan/liuyao/controller/user/UserController.java`
- 改动：8处方法调用更新
- 代码质量：提升（依赖更明确）
