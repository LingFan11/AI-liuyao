# 六爻智能解卦系统需求文档

## 功能概述

六爻智能解卦系统是一个基于中国传统易经六爻占卜方法的智能预测平台。系统通过模拟传统的六爻起卦过程，结合AI技术提供智能化的卦象解释和预测分析，帮助用户进行决策参考。系统支持多种起卦方式，提供专业的卦象分析，并记录用户的占卜历史，实现个性化的占卜体验。

## 功能需求

### 1. 用户管理模块

#### 1.1 用户注册与登录
**用户故事**: 作为一个新用户，我想要注册账号并登录系统，以便保存我的占卜记录和获得个性化服务。

**验收标准**:
1. **当**用户访问注册页面**时**，系统**应该**提供用户名、密码、邮箱和手机号的输入框
2. **当**用户提交有效的注册信息**时**，系统**应该**创建新账号并自动登录
3. **当**用户输入已存在的用户名或邮箱**时**，系统**应该**提示"该用户名/邮箱已被注册"
4. **当**用户登录时输入错误的密码**时**，系统**应该**提示"用户名或密码错误"
5. **当**用户连续3次登录失败**时**，系统**应该**锁定账号15分钟

#### 1.2 用户信息管理
**用户故事**: 作为一个注册用户，我想要管理我的个人信息，以便保持信息的准确性。

**验收标准**:
1. **当**用户访问个人中心**时**，系统**应该**显示用户的基本信息（昵称、头像、签名）
2. **当**用户修改个人信息**时**，系统**应该**实时保存并更新显示
3. **当**用户上传头像超过5MB**时**，系统**应该**提示"图片大小不能超过5MB"

### 2. 起卦模块

#### 2.1 手动起卦
**用户故事**: 作为一个用户，我想要通过手动投掷硬币的方式起卦，以便遵循传统的占卜方式。

**验收标准**:
1. **当**用户选择手动起卦**时**，系统**应该**提供模拟投掷三枚硬币的界面
2. **当**用户点击投掷按钮**时**，系统**应该**显示三枚硬币的正反面结果
3. **当**用户完成六次投掷**时**，系统**应该**自动生成完整的六爻卦象
4. **如果**用户中途退出**那么**系统**应该**提示"是否保存当前起卦进度"
5. **当**用户选择保存进度**时**，系统**应该**在下次进入时恢复之前的起卦状态

#### 2.2 自动起卦
**用户故事**: 作为一个用户，我想要快速自动起卦，以便节省时间获得占卜结果。

**验收标准**:
1. **当**用户选择自动起卦**时**，系统**应该**提供"时间起卦"、"数字起卦"、"随机起卦"三种方式
2. **当**用户选择时间起卦**时**，系统**应该**基于当前时间自动生成六爻
3. **当**用户选择数字起卦**时**，系统**应该**要求输入三个数字（1-999）
4. **如果**用户输入的数字超出范围**那么**系统**应该**提示"请输入1-999之间的数字"
5. **当**用户选择随机起卦**时**，系统**应该**使用随机算法生成六爻

#### 2.3 卦象记录
**用户故事**: 作为一个用户，我想要在起卦时记录问题和背景，以便日后回顾占卜的上下文。

**验收标准**:
1. **当**用户起卦前**时**，系统**应该**提供输入框让用户填写占卜问题（必填）
2. **当**用户输入占卜问题少于5个字**时**，系统**应该**提示"请详细描述您的问题（至少5个字）"
3. **当**用户起卦时**时**，系统**应该**允许选择占卜类别（事业、感情、健康、财运、学业、其他）
4. **当**用户完成起卦**时**，系统**应该**记录起卦时间、地点（可选）、天气（自动获取）

### 3. 解卦模块

#### 3.1 基础卦象解释
**用户故事**: 作为一个用户，我想要获得卦象的基础解释，以便了解卦象的含义。

**验收标准**:
1. **当**系统生成卦象后**时**，**应该**显示本卦和变卦（如有）的图形
2. **当**用户查看卦象**时**，系统**应该**显示卦名、卦辞、爻辞
3. **当**存在变爻**时**，系统**应该**高亮显示变爻位置并说明变化
4. **当**用户点击查看详情**时**，系统**应该**提供卦象的传统易经解释

#### 3.2 AI智能解卦
**用户故事**: 作为一个用户，我想要获得AI结合我的问题的个性化解释，以便得到更准确的指导。

**验收标准**:
1. **当**用户提交占卜问题后**时**，AI**应该**结合问题内容生成针对性的解释
2. **当**AI解析卦象**时**，**应该**包含以下内容：卦象总体分析、问题具体分析、吉凶判断、行动建议
3. **如果**用户选择了占卜类别**那么**AI**应该**基于类别提供专业领域的解释
4. **当**AI生成解释**时**，**应该**在30秒内完成
5. **如果**AI解析超时**那么**系统**应该**提示"解析中，请稍候"并显示进度

#### 3.3 六爻分析
**用户故事**: 作为一个高级用户，我想要查看详细的六爻分析，以便深入理解卦象。

**验收标准**:
1. **当**用户选择查看六爻分析**时**，系统**应该**显示每一爻的详细信息
2. **当**显示爻的信息**时**，**应该**包含：爻位、阴阳属性、六亲、世应、动静状态
3. **当**存在动爻**时**，系统**应该**分析动爻对卦象的影响
4. **当**用户点击某一爻**时**，系统**应该**显示该爻的具体含义和作用

### 4. 历史记录模块

#### 4.1 占卜历史查询
**用户故事**: 作为一个用户，我想要查看我的占卜历史，以便回顾和分析过往的占卜结果。

**验收标准**:
1. **当**用户访问历史记录页面**时**，系统**应该**按时间倒序显示占卜记录列表
2. **当**显示记录列表**时**，每条记录**应该**包含：日期、问题摘要、卦象名称、简要结果
3. **当**用户点击某条记录**时**，系统**应该**显示完整的占卜详情
4. **当**历史记录超过20条**时**，系统**应该**分页显示（每页20条）
5. **当**用户搜索关键词**时**，系统**应该**筛选包含关键词的占卜记录

#### 4.2 占卜统计分析
**用户故事**: 作为一个用户，我想要查看我的占卜统计，以便了解我的占卜倾向和规律。

**验收标准**:
1. **当**用户查看统计页面**时**，系统**应该**显示占卜总次数、最常占卜类别、最常出现的卦象
2. **当**统计时间范围可选**时**，**应该**提供：最近7天、最近30天、最近一年、全部
3. **当**用户选择时间范围**时**，系统**应该**实时更新统计数据
4. **如果**某个时间段内没有数据**那么**系统**应该**显示"该时间段暂无占卜记录"

#### 4.3 收藏管理
**用户故事**: 作为一个用户，我想要收藏重要的占卜记录，以便快速查找和参考。

**验收标准**:
1. **当**用户查看占卜记录**时**，系统**应该**提供收藏按钮
2. **当**用户点击收藏**时**，系统**应该**将记录添加到收藏列表并显示"已收藏"
3. **当**用户查看收藏列表**时**，系统**应该**单独显示所有收藏的占卜记录
4. **当**用户取消收藏**时**，系统**应该**从收藏列表中移除该记录
5. **当**收藏记录超过100条**时**，系统**应该**提示"收藏数量已达上限"

### 5. 知识库模块

#### 5.1 易经知识学习
**用户故事**: 作为一个用户，我想要学习易经和六爻的基础知识，以便更好地理解占卜结果。

**验收标准**:
1. **当**用户访问知识库**时**，系统**应该**提供分类的知识内容：基础概念、六十四卦详解、六爻基础、占卜方法
2. **当**用户选择某个卦象**时**，系统**应该**显示该卦的详细资料（卦象图、卦辞、爻辞、白话解释）
3. **当**用户学习时**时**，系统**应该**记录学习进度
4. **当**知识内容包含专业术语**时**，系统**应该**提供术语解释的弹窗或链接

#### 5.2 案例分享
**用户故事**: 作为一个用户，我想要查看占卜案例，以便学习如何解读卦象。

**验收标准**:
1. **当**用户查看案例**时**，系统**应该**显示经典占卜案例和解析
2. **当**案例显示**时**，**应该**包含：问题背景、卦象、解析过程、实际验证
3. **当**用户可以筛选案例**时**，**应该**提供按类别（事业、感情等）筛选的功能
4. **如果**案例包含用户分享**那么**系统**应该**隐藏用户隐私信息

### 6. 系统管理模块

#### 6.1 数据管理
**用户故事**: 作为系统管理员，我想要管理系统数据，以便维护系统正常运行。

**验收标准**:
1. **当**管理员登录后台**时**，系统**应该**提供用户管理、占卜记录管理、知识库管理功能
2. **当**管理员查看用户列表**时**，**应该**能够搜索、查看详情、禁用/启用账号
3. **当**管理员管理知识库**时**，**应该**能够添加、编辑、删除知识内容
4. **当**管理员执行敏感操作**时**，系统**应该**记录操作日志

#### 6.2 AI模型管理
**用户故事**: 作为系统管理员，我想要配置AI模型参数，以便优化解卦质量。

**验收标准**:
1. **当**管理员访问AI配置**时**，系统**应该**显示当前使用的模型和参数
2. **当**管理员修改参数**时**，系统**应该**提供测试功能验证效果
3. **如果**修改的参数无效**那么**系统**应该**回滚到上一个有效配置
4. **当**AI服务不可用**时**，系统**应该**自动切换到备用解析方案

## 非功能性需求

### 性能需求
1. **当**用户进行起卦操作**时**，系统响应时间**应该**小于1秒
2. **当**AI解析卦象**时**，处理时间**应该**小于30秒
3. **当**系统并发用户数达到1000**时**，**应该**保持正常响应速度
4. **当**数据库记录超过100万条**时**，查询速度**应该**保持在3秒内

### 安全需求
1. **当**用户密码存储**时**，系统**应该**使用加密算法（如BCrypt）
2. **当**用户会话超过30分钟无操作**时**，系统**应该**自动登出
3. **当**检测到异常登录行为**时**，系统**应该**发送安全提醒
4. **当**传输敏感数据**时**，系统**应该**使用HTTPS加密

### 可用性需求
1. **当**系统部署**时**，**应该**保证99.9%的可用性
2. **当**系统出现故障**时**，**应该**在5分钟内自动恢复或切换到备用服务
3. **当**数据备份**时**，系统**应该**每日自动备份一次
4. **如果**主数据库故障**那么**系统**应该**自动切换到备用数据库

### 兼容性需求
1. **当**用户使用Web浏览器**时**，系统**应该**支持Chrome、Firefox、Safari、Edge的最新两个版本
2. **当**用户使用移动设备**时**，系统**应该**提供响应式设计适配不同屏幕
3. **当**系统API对外提供**时**，**应该**支持RESTful接口标准
4. **如果**未来需要移动应用**那么**系统**应该**提供统一的后端API

## 约束条件

### 技术约束
1. 系统基于Spring Boot 3.x框架开发
2. 使用MySQL 8.0作为主数据库
3. 集成LangChain4J实现AI功能
4. 使用Redis缓存热点数据

### 业务约束
1. 免费用户每日占卜次数限制为3次
2. 付费用户每日占卜次数限制为20次
3. AI解析功能需要用户等级达到2级
4. 历史记录保存期限为1年

## 成功标准

1. 系统上线后首月注册用户达到1000人
2. 日活跃用户占比达到30%
3. AI解卦准确度用户满意度达到85%以上
4. 系统稳定性达到99.9%可用性
5. 用户平均会话时长超过10分钟
6. 付费转化率达到5%
